# Критерии приёмки ST67 Сметчика v0.2.0

Критерии проверяют наблюдаемое поведение, а не наличие обещания в тексте.

## Вход и режим

- Без явного `light`/`full` Сметчик задаёт один сгруппированный вопрос и не начинает смысловую проверку.
- Режим не выбирается по размеру, формату или формулировке «проверь смету».
- Уже доступные режим, цель и контекст повторно не запрашиваются.

## Охват

- `light`: инвентаризирован каждый вход; выполнен обязательный макроминимум или названо ограничение; процентной выборки нет; `row_level_checked=false`; `sampling_strategy="none"`; нет утверждения о проверке каждой позиции.
- `full`: каждая надёжно извлечённая позиция/формула/связь имеет состояние; все непроверенные диапазоны названы; процентной выборки нет.
- В обоих режимах итог ограничен фактическим охватом; отсутствует обещание эквивалента экспертизы или абсолютной полноты.

## Форматы и безопасность

- Excel: формула и кэш различаются; внешние ссылки/макросы не исполняются; скрытые области учтены; оригинал не изменён.
- Скан-PDF: локальный OCR `rus+eng` применяется только при доступности; без OCR страницы получают точное ограничение, а не чистый итог.
- Известный XML/GGE: схема/версия и XPath зафиксированы; DTD/сеть отключены.
- Неизвестный XML: только структурный инвентарь, без смысловых сумм и нормативных findings.
- ZIP: path traversal, ссылки, коллизии и архивная бомба блокируются; временные данные очищаются.
- Ни один документ не загружается во внешний сервис.

## Контроли

- Иерархия задания/оснований → ведомости объёмов/дефектного акта → ЛСР → ОСР → ССР прослежена в доступном составе.
- Объёмы, единицы, расценки, коэффициенты, индексы/уровень цен, материалы/оборудование, КАЦ, НДС/доставка/заготовительно-складские, накладные/прибыль, временные/непредвиденные и ПИР/изыскания проверены либо для каждого неприменимого/заблокированного блока дана причина.
- Дубли/пропуски, структура стоимости и удельные показатели не выдаются за нормативное нарушение без отдельного основания.
- Капремонт, снос и ОКН не приводят к проектным/инженерным выводам.

## Доказательства

- Finding содержит severity, confidence, одно утверждение, точный локатор, расчёт или `not_applicable`, source ID и действие.
- Severity и confidence независимы; вопросы и ограничения вынесены отдельно.
- Нет скрытых допусков; любой допуск раскрыт с единицей и источником/согласием.
- Категоричный нормативный вывод содержит live-проверенную редакцию и применимость официального источника.
- Результат проходит JSON Schema `assets/smetchik.result.v1.schema.json`.

## Выход и изменения

- По умолчанию результат только в чате и файловые изменения отсутствуют.
- Команда сохранить создаёт новый файл без перезаписи.
- Команда исправить принимается только после отдельной прямой команды и только как запрос `smetchik.corrections.v1` с точным `source_sha256`.
- Для XLSX/XLSM `confirmed` создаёт исправленную копию и журнал, а `disputed` сохраняет исходное значение и добавляет аннотацию; PDF, XML/GGE/MGE и XLS получают sidecar.
- `output` и `changelog` работают как `create-only` и создаются только по новым различным путям; существующий путь, несовпадение `source_sha256`/`expected_old` и формула либо активное строковое выражение отклоняются без частичного результата.
- SHA-256 оригиналов до и после исправления совпадает.
- НМЦК, закупка, КС-2/КС-3, подлинность, инженерная безопасность и заключение госэкспертизы явно остаются вне результата.

## Статическая валидация пакета

Из корня плагина должны успешно выполняться:

```bash
python3 <skill-creator>/scripts/quick_validate.py skills/smetchik
python3 <plugin-creator>/scripts/validate_plugin.py .
python3 -m json.tool skills/smetchik/assets/smetchik.result.v1.schema.json
python3 -m json.tool skills/smetchik/assets/smetchik.corrections.v1.schema.json
"$HOME/.local/share/smetchik/venv/bin/python" -m pytest -p no:cacheprovider -q \
  tests/test_artifact_writer.py tests/test_runtime.py
```

Runtime принимается только если `--verify-only` подтверждает все версии полного lock-файла и не обнаруживает неожиданных пакетов; вне lock разрешены только bootstrap-инструменты `pip`, `setuptools` и `wheel`. Автоматические тесты используют только обезличенные синтетические фикстуры. Согласованный внешний приёмочный прогон выполняется отдельно; его документы и результаты не включаются в пакет.

## Ворота выпуска и порядок приёмки

Каждые ворота фиксируются отдельным доказательством. Прохождение более позднего шага не закрывает непройденный ранний шаг.

| ID | Условие PASS | Доказательство |
|---|---|---|
| `GATE-AUTOMATED` | Выполнен полный `pytest` всего репозитория без падений и неожиданных пропусков. | Команда, код возврата и итоговый счётчик тестов из финального снимка. |
| `GATE-VALIDATORS` | Пройдены штатные `quick_validate.py` для скилла и `validate_plugin.py` для плагина. | Вывод обоих валидаторов с путями проверенного снимка. |
| `GATE-SCHEMAS` | Обе JSON-схемы синтаксически корректны, компилируются строгим Ajv 2020 и проходят позитивные и негативные контрактные тесты. | `json.tool`, strict Ajv и профильные schema/result tests. |
| `GATE-XSD` | В пакет не включены XSD; `schema_manager.py fetch --all` устанавливает только проверенные архивы и XSD из реестра. Без локально установленной нужной схемы XML/GGE получает `schema_not_installed` и остаётся structure-only без семантической или стоимостной проверки. | Профильные XML/XSD и schema-manager тесты, `schema_manager.py verify`, перечень проверенных установленных схем. |
| `GATE-RUNTIME` | Чистое отдельное окружение устанавливается по точному lock-файлу; `--verify-only` подтверждает версии, отсутствие неожиданных пакетов и отсутствие сервисов. | Вывод bootstrap/verify и инвентарь окружения без секретов. |
| `GATE-INSTALLED` | После `codex plugin marketplace add RomanovVIII/st67-smetchik --ref v0.2.0` плагин `st67-smetchik@st67-smetchik` установлен из repository marketplace; `codex plugin list` показывает ожидаемые имя, версию и источник. | Независимый installed readback после штатной установки из публичного GitHub по тегу `v0.2.0`. |
| `GATE-FRESH-EXPLICIT` | В новой задаче явный вызов `$smetchik` загружает навык, требует режим и паспорт и не зависит от конкретного проекта. | Транскрипт свежей задачи в изолированной пользовательской среде. |
| `GATE-FRESH-IMPLICIT` | В другой новой задаче обычная фраза «проверь смету» по смыслу маршрутизируется к Сметчику; режим не выбирается автоматически. | Транскрипт независимого неявного запуска. |
| `GATE-REAL-RUN` | После отдельного согласования выполнен один внешний read-only прогон на реальном или обезличенном пакете вне репозитория. | Хэшированный инвентарь и статус прогона; материалы и результаты в репозиторий не копируются. |
| `GATE-MANUAL` | Независимый reviewer вручную оценивает реальный отчёт: охват, локаторы, выводы, вопросы и ограничения понятны и предметно пригодны. | Зафиксированная ручная оценка и перечень обязательных исправлений, если они есть. |
| `GATE-NETWORK` | Доказано, что пользовательские файлы не передавались в сеть; официальные источники открывались без передачи содержимого входного пакета. | Наблюдаемый локальный маршрут обработки и отрицательная проверка сетевых upload-действий. |
| `GATE-READONLY` | Проверка по умолчанию не создаёт и не изменяет пользовательские файлы, базы данных, таблицы, сервисы или конфигурацию. | Снимки входных хэшей и файловой области до и после запуска. |
| `GATE-NO-OVERWRITE` | При отдельно подтверждённом исправлении оригиналы неизменны, выход и журнал создаются только по новым путям; существующие пути отклоняются до записи. | Совпадающие SHA-256 оригиналов и негативный тест create-only. |

Установка, реальный прогон и ручная приёмка не подменяются синтетическими тестами.
